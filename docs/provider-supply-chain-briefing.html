03 · The program

One gate. Everything flows through it.

We put a governed mirror between the internet and every Terraform run. A single human-reviewed approval list drives three things at once: what can be installed (the mirror), what's allowed to run (policy checks on every plan), and the proof it was verified (signatures on every artifact).

Approval is presence. A provider version exists for engineers only after Security merges it. There is no side channel and no second list to drift.
Every plan is checked. Policy gates in CI and the deploy pipeline block any run pinning an unapproved version — even code already on disk.
Every artifact is provable. Cryptographic verification at intake, signed attestations on the shelf, and an audit trail answering "what code, when, approved by whom."
04 · The payoff moment

From CVE to org-wide block: minutes

Today, responding to a compromised provider means a manual scramble across hundreds of repositories with no way to confirm completion. With the program, revocation is one reviewed line — and the systems converge on their own.

T+0

One-line pull request removes the version from the approval list, with the CVE linked in the diff. Security reviews and merges.

T+2 MIN

The mirror stops serving it. No machine in the company can install that version anymore — laptops included.

T+3 MIN

Policy gates go live. Every subsequent plan that still pins the version is blocked, with the CVE reference in the failure message.

T+5 MIN

Caches flush. Deployment restart rebuilds runner caches from the mirror — the binary is physically gone from infrastructure.

T+HOURS

The fleet moves itself. Automated dependency updates walk every repository to the nearest approved version; stragglers stay blocked until they move.

Presence in the mirror is the approval.
Absence is the revocation.

05 · The landscape

Who operates this way?

Honest answer: the organizations with the most to lose already do — and almost nobody else. In Q1 2025, 66% of blocked open-source malware attacks were aimed at financial services firms (Sonatype): the sector that runs gates is the sector attackers test hardest.

Standard where stakes are highest

  • Banks & regulated finance — artifact firewalls and private mirrors (Artifactory, Nexus, Sonatype Firewall) are table stakes for dependency intake
  • Defense & air-gapped environments — nothing installs from the public internet, ever
  • Big-tech internal curation — Google-style third-party review: code is vendored, reviewed, and versioned before any engineer can use it
  • Where standards point — NIST SSDF and SLSA both prescribe exactly this: verified provenance, controlled distribution, revocable trust

What almost no one does yet

  • Applying it to infrastructure-as-code providers — the third-party code that runs with the broadest cloud credentials of all
  • One reviewed list driving everything — the same approval simultaneously feeds the mirror, the policy checks, and the signed evidence trail, so they can never disagree
  • Minutes-scale revocation as a designed capability, not an incident-day improvisation
  • Doing it with zero new running services — static storage plus existing CI, not another platform to operate

This is cheap differentiation: the control posture of a tier-one bank, built from commodity parts, in the one place our industry hasn't looked yet.

06 · The ask

Four phases. No new platforms.

The design is deliberately boring to operate: static cloud storage, our existing CI, our existing registries. No new services to run, patch, or page on. Engineering designs are complete and reviewed; the first phase also eliminates a current reliability problem (rate-limit failures on large runs) on day one.

PH·1

Stop the bleeding

Provider caching on the deploy platform — kills today's rate-limit failures on large changes. Ships immediately, independent of everything else.

PH·2

Build the shelf

The governed mirror: inventory what's in use, seed the approval list, verify and publish every artifact with signatures.

PH·3

Close the gate

Cut all installation over to the mirror. From this moment, unapproved code cannot enter — structurally, not by policy memo.

PH·4

Wire the governance

Policy checks at every choke point, automated version flow, exception workflow with expiry, compliance dashboards.
